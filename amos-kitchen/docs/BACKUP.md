## סקירה כללית

### מה נשמר במערכת?
- **לקוחות** - פרטי לקוחות והעדפותיהם
- **מנות** - רשימת המנות והמחירים
- **הזמנות** - כל ההזמנות ההיסטוריות
- **משתמשים** - פרטי המשתמשים המורשים

### מצב הגיבוי הנוכחי

| תוכנית Firebase | גיבוי אוטומטי | הערות |
|----------------|--------------|-------|
| Spark (חינם) | ❌ לא | יש לבצע גיבוי ידני |
| Blaze (בתשלום) | ✅ כן | Point-in-time recovery זמין |

> ⚠️ **חשוב**: אם אתם בתוכנית Spark (חינם), **חובה** לבצע גיבויים ידניים!

## גיבוי ידני דרך האפליקציה

### ייצוא הזמנות

1. התחבר למערכת
2. עבור לדף **הזמנות**
3. לחץ על כפתור **"ייצוא"** (אייקון אקסל)
4. קובץ Excel יירד למחשב
5. שמור את הקובץ בתיקייה עם תאריך

**שם קובץ מומלץ**: `orders_backup_2026-01-30.xlsx`

### ייצוא לקוחות

1. עבור לדף **לקוחות**
2. לחץ על כפתור **"ייצוא"**
3. שמור את הקובץ

**שם קובץ מומלץ**: `customers_backup_2026-01-30.xlsx`

### ייצוא מנות

1. עבור לדף **מנות**
2. לחץ על כפתור **"ייצוא"** (אם קיים)
3. או העתק את הרשימה ידנית

## גיבוי דרך Firebase Console

### שיטה 1: ייצוא ידני

1. גש ל-[Firebase Console](https://console.firebase.google.com)
2. בחר את הפרויקט
3. **Firestore Database** → לחץ על ⋮ (שלוש נקודות)
4. בחר **"Export all documents"**
5. בחר יעד ב-Cloud Storage
6. לחץ **"Export"**

### שיטה 2: ייצוא לפי Collection

1. Firebase Console → Firestore Database
2. לחץ על Collection (למשל `customers`)
3. לחץ על ⋮ → **"Export collection"**
4. חזור על הפעולה לכל Collection

### Collections לגיבוי

| Collection | תיאור | חשיבות |
|------------|--------|--------|
| `customers` | רשימת לקוחות | קריטי |
| `orders` | כל ההזמנות | קריטי |
| `dishes` | רשימת מנות | גבוה |
| `config` | הגדרות מערכת | גבוה |
| `counters` | מוני הזמנות | בינוני |
| `users` | פרופילי משתמשים | בינוני |

## שחזור נתונים

### שחזור מקובץ Excel

במקרה של אובדן נתונים, יש לפנות לתמיכה טכנית עם:
1. קובץ הגיבוי האחרון
2. תיאור הבעיה
3. התאריך האחרון שהנתונים היו תקינים

### שחזור מ-Firebase Backup

1. Firebase Console → Firestore Database
2. לחץ על ⋮ → **"Import data"**
3. בחר את קובץ הגיבוי
4. אשר את הייבוא

> ⚠️ **זהירות**: ייבוא נתונים עלול לדרוס נתונים קיימים!

## בדיקת תקינות גיבויים

### בדיקה חודשית

**פתח גיבוי אקראי ובדוק:**

1. **פתיחה תקינה**
   - [ ] הקובץ נפתח ב-Excel
   - [ ] אין שגיאות קידוד (עברית תקינה)

2. **שלמות הנתונים**
   - [ ] כל העמודות קיימות
   - [ ] יש שורות נתונים (לא ריק)
   - [ ] מספר הרשומות הגיוני

3. **דגימה אקראית**
   - [ ] בחר 3 רשומות אקראיות
   - [ ] ודא שהן תואמות למה שבמערכת

### תיעוד בדיקה

צור קובץ `backup_verification_log.txt`:

```

קובץ שנבדק: customers_backup_2026-01-15.xlsx
מספר רשומות: 150
סטטוס: תקין
הערות: -
```

## אחסון גיבויים

### כללי אחסון

1. **שמור ב-3 מקומות לפחות**
   - המחשב המקומי
   - שירות ענן (Google Drive / Dropbox)
   - דיסק חיצוני / USB

2. **ארגון תיקיות**
   ```
   גיבויים/
   ├── 2026/
   │   ├── 01-ינואר/
   │   │   ├── customers_2026-01-07.xlsx
   │   │   ├── orders_2026-01-07.xlsx
   │   │   ├── customers_2026-01-14.xlsx
   │   │   └── orders_2026-01-14.xlsx
   │   ├── 02-פברואר/
   │   └── ...
   ```

3. **שמירת גיבויים**
   - גיבויים שבועיים: 8 שבועות אחרונים
   - גיבויים חודשיים: 12 חודשים אחרונים
   - גיבוי שנתי: לשמור לצמיתות
